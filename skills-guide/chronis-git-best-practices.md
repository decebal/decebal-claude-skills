# Chronis in Git Repositories — Best Practices

Guide for using the chronis (`cn`) CLI in git-tracked projects.

## .gitignore

Always ignore the `.chronis/` directory. It contains local event store data (WAL, Parquet files, config) that is machine-specific and should never be committed.

Add this to your `.gitignore`:

```gitignore
# Chronis (local event store data)
.chronis/
```

### What lives in `.chronis/`

| Path | Contents | Why ignored |
|------|----------|-------------|
| `.chronis/config.toml` | Local store configuration | Machine-specific paths, ports |
| `.chronis/storage/*.parquet` | Parquet event files | Binary data, grows large, machine-local |
| `.chronis/wal/` | Write-ahead log segments | Transient durability layer, not portable |

## There is no second directory

`.chronis/` is the whole store. Tasks are events in the same WAL and Parquet
files as everything else — there is no separate task database, no SQLite file,
and no JSONL export to track.

`.beads/` belongs to the older `bd` and `br` CLIs. The only chronis command that
mentions it reads it:

```bash
cn migrate-beads    # import .beads/issues.jsonl into chronis events
```

So if you see `.beads/` in a chronis project, it is either a leftover from before
the migration or a mistake in the doc you are reading.

## tasks/ — PRDs and snapshots

The `tasks/` directory holds PRDs generated by `claude-prd`. By default it's gitignored in the monorepo. For projects where PRDs should be tracked:

```bash
# Remove tasks/ from .gitignore, or track specific files:
git add -f tasks/prd-my-feature.md
```

## Recommended .gitignore block

```gitignore
# Chronis (local event store data — tasks included)
.chronis/

# Claude Code session state
.claude/

# PRD task files (optional — track if you want PRD history)
# tasks/
```

## Branch workflow

When using claude with chronis for feature work:

1. **Create a feature branch** before generating beads
2. **PRDs** can be committed to the branch for review context
3. **Beads** stay local (gitignored) — they're execution state, not source
4. **Agent commits** land on the feature branch as normal commits
5. **PR the branch** when the epic completes and all quality gates pass

```bash
git checkout -b feat/my-feature
claude "create a prd for my feature"           # generates tasks/prd-my-feature.md
claude "create beads from tasks/prd-my-feature.md"  # writes tasks into .chronis/ (gitignored)
claude "work the ready beads: cn ready --toon, claim each, implement, run its quality gates, cn done"                 # agents work, commit to branch
git push -u origin feat/my-feature
gh pr create
```

## Multi-developer workflow

Each developer runs their own local chronis instance. There is no shared state — beads are per-machine. If multiple developers work on the same epic:

- Share the PRD (commit `tasks/prd-*.md` to the branch)
- Each developer creates their own beads from the PRD
- Coordinate story assignment manually or via Linear/GitHub issues
- All commits land on the same feature branch

## Data cleanup

Chronis data accumulates over time. Clean up periodically:

```bash
# Remove all local chronis data — events, WAL, config, and every task
rm -rf .chronis/
```

This is safe in the sense that nothing shared is lost: `.chronis/` is local
ephemeral data, and the tasks in it can be recreated from the PRD. It is not
undoable, though — there is no export, so anything recorded only in a task's
event history goes with it.
